# Independent venue data for the fixed six-month delivery-basis rule

Reviewed 2026-09-26. This is a source and feasibility assessment, not a return estimate or permission to trade. The existing rule buys BTC and ETH spot and sells the corresponding USDT-settled June future on January 1 or December future on July 1, around 00:00 UTC; it closes both sides at 00:00 UTC two days before expiry. The existing five-minute entry/exit window and cost/margin assumptions must be stated unchanged before any cross-venue replay. An exchange change also changes fees, contract increments, liquidation mechanics, and possibly the stablecoin, so it is an independent strategy implementation rather than a fill validation of Binance orders.

## Decision

| Venue and instrument | Observed coverage for this rule | Historical trade tape | Historical bid/ask depth | Main limitation |
| --- | --- | --- | --- | --- |
| OKX BTC/ETH spot plus USDT-margined June/December expiry futures | The required January/July future contracts are present in sampled 2022-2025 entry-day archives; the January 2026 June contracts are present too. | Public daily ZIP/CSV archives; actual target contract IDs and first-five-minute trade counts checked below. | Official downloadable 400-level L2 begins March 2023; a BTC-USDT futures-family link for 2024-01-01 was returned, but its contents were not downloaded. | [OKX says the final BTC/ETH USDT expiry contracts expired 2026-06-26](https://www.okx.com/en-gb/help/announcement-on-discontinuing-btc-and-eth-usdt-margined-expiry-futures); there can be no same-product July-December 2026 observation. |
| Bybit BTC/ETH spot plus USDC expiry futures | Public archives show July 2023, both 2024 half-years, and both 2025 half-years at the relevant entry dates. | Public daily gzip CSV archives for spot and the named futures. | No historical depth file was verified; the documented REST order-book endpoint is a current snapshot. | USDC is a different settlement asset, and the available archives do not establish historical execution depth. |
| Bybit BTC/ETH spot plus USDT expiry futures | June 2025 contracts were archived only from 2025-04-01, so 2025 H1 has no January entry. December 2025, June 2026, and December 2026 contracts cover their July/January entry dates. | Public daily gzip CSV archives. | No historical depth file was verified. | **Both December 2026 future archives contain zero trades in the fixed July 1, 00:00-00:04 UTC window**, so an unchanged trade-price entry is unavailable on this venue for 2026 H2. |

The OKX historical-data page advertises tick trades from September 2021, candles from July 2023, and high-resolution L2 from March 2023 [at its first-party download page](https://www.okx.com/en-sg/historical-data). The Bybit public archive has separate [spot](https://public.bybit.com/spot/) and [derivatives](https://public.bybit.com/trading/) directories; its [official API documentation](https://bybit-exchange.github.io/docs/v5/market/recent-trade) links to archived trades. These advertised start dates alone do not prove every individual instrument-day; the observations below are direct archive checks.

## OKX: direct archive evidence and contract comparability

The public historical-data page's first-party application requests download links from `https://www.okx.com/priapi/v5/broker/public/trade-data/download-link`. A read-only request for `module=1`, `instType=FUTURES`, `instFamilyList=["BTC-USDT"]`, daily 2024-01-01 returned a [future-family ZIP](https://static.okx.com/cdn/okex/traderecords/trades/daily/20240101/BTC-USDT-futureschain-trades-2024-01-01.zip?v=999); the analogous `SPOT` query with `instIdList=["BTC-USDT","ETH-USDT"]` returned [spot ZIPs](https://static.okx.com/cdn/okex/traderecords/trades/daily/20220101/BTC-USDT-trades-2022-01-01.zip?v=999). Both requests and file downloads worked without a login or API key in this review. No tariff was charged or displayed for these public files, but availability and terms may differ by region. The futures ZIP is a **family** archive containing several expiries, so filtering by `instrument_name` is mandatory.

Observed URL templates, with `BTC` replaceable by `ETH`:

```text
https://static.okx.com/cdn/okex/traderecords/trades/daily/YYYYMMDD/BTC-USDT-trades-YYYY-MM-DD.zip?v=999
https://static.okx.com/cdn/okex/traderecords/trades/daily/YYYYMMDD/BTC-USDT-futureschain-trades-YYYY-MM-DD.zip?v=999
```

Each inspected ZIP held one CSV named like `BTC-USDT-trades-2022-01-01.csv` or `BTC-USDT-futureschain-trades-2024-01-01.csv`, with header `instrument_name,trade_id,side,price,size,created_time`. `created_time` is a 13-digit Unix-millisecond UTC timestamp. The first row of the nominal 2022-01-01 [spot archive](https://static.okx.com/cdn/okex/traderecords/trades/daily/20220101/BTC-USDT-trades-2022-01-01.zip?v=999) is timestamp `1640966400003`, i.e. 2021-12-31 16:00:00.003 UTC: the archive partition follows UTC+8, so select the exact UTC interval from timestamps, not the ZIP date. The [OKX market-trades API schema](https://www.okx.com/docs-v5/en/) defines `side` as the **taker** side, spot `size` in base asset, and futures `size` in contracts. For the dated USDT futures, a [2020 first-party contract-value adjustment](https://www.okx.com/en-us/help/adjustment-of-face-value-for-usdt-margined-perpetual-swap-futures-trading) set BTC to 0.01 BTC and ETH to 0.1 ETH per contract; confirm any later instrument-specific change before sizing a replay.

Sampled future entry-day archives also contained the June/December target for 2024 and 2025; January 2026 contained `BTC-USDT-260626` and `ETH-USDT-260626`. On 2026-01-01 the BTC target had **zero** trades in the first five minutes, although it had later trades that day, so an exact five-minute *trade-price* fill is not available for that leg. Direct archive links follow the same pattern above. [OKX's expiry-futures specification](https://www.okx.com/en-gb/help/expiry-futures) says these contracts settle in USDT and the relevant quarterly expiry is the last Friday of June/December at 08:00 UTC. The 2026 product discontinuation is documented separately [by OKX](https://www.okx.com/en-gb/help/announcement-on-discontinuing-btc-and-eth-usdt-margined-expiry-futures).

For historical book depth, a public request for `module=4` (400-level L2), `instType=FUTURES`, family `BTC-USDT`, and 2024-01-01 returned [this 159.77 MB futures-family tar.gz](https://static.okx.com/cdn/okx/match/orderbook/L2/400lv/daily/20240101/BTC-USDT-futureschain-L2orderbook-400lv-2024-01-01.tar.gz). Its contents, timestamps and target-contract quotes have **not** been verified. The [official portal's March 2023 L2 start](https://www.okx.com/en-sg/historical-data) means this first-party service cannot supply 2022 bid/ask history; this is an inference from its advertised scope. As a distinct mechanism, [OKX's daily settlement documentation](https://www.okx.com/en-gb/help/expiry-futures-daily-settlement-mechanism) says cross-margin expiry positions settle P/L at 08:00 UTC. A Binance wallet/margin replay cannot simply be reused unchanged.

For an illustrative current standard-tier cost reference, an [OKX fee notice](https://www.okx.com/en-gb/help/advance-notice-spot-and-futures-trading-fee-adjustment) lists 0.10% spot taker and 0.05% futures taker, but those rates are not proof of a particular user's fee schedule or 2022-2023 historical fees. The [authenticated fee-rate endpoint](https://www.okx.com/docs-v5/en/) and the account's applicable region/tier would need confirmation before claiming net executable profit.

## Bybit: current USDT continuation and archive limits

Bybit documents both [USDT-settled dated futures](https://www.bybit.com/en/help-center/article/Introduction-to-USDT-Perpetual-Expiry-Contract) and [linear-futures instrument metadata](https://bybit-exchange.github.io/docs/v5/market/instrument). A public `GET /v5/market/instruments-info?category=linear&symbol=BTCUSDT-25DEC26` (and ETH equivalent) returned `LinearFutures`, `Trading`, `quoteCoin=settleCoin=USDT`, delivery timestamp `1798185600000` (2026-12-25 08:00 UTC); the observed minimum and increment are 0.001 BTC or 0.01 ETH. These are current API observations, not evidence of an account's permission to trade: [BTC endpoint](https://api.bybit.com/v5/market/instruments-info?category=linear&symbol=BTCUSDT-25DEC26), [ETH endpoint](https://api.bybit.com/v5/market/instruments-info?category=linear&symbol=ETHUSDT-25DEC26).

The public [BTC December 2026 directory](https://public.bybit.com/trading/BTCUSDT-25DEC26/) and [ETH directory](https://public.bybit.com/trading/ETHUSDT-25DEC26/) list daily files from 2026-01-09 through the observed 2026-09-25 file. Both include July 1, as do the [BTC](https://public.bybit.com/spot/BTCUSDT/) and [ETH](https://public.bybit.com/spot/ETHUSDT/) spot directories. For comparison, Bybit's USDT June 2025 futures [BTC](https://public.bybit.com/trading/BTCUSDT-27JUN25/) and [ETH](https://public.bybit.com/trading/ETHUSDT-27JUN25/) directories begin 2025-04-01, after the fixed January entry. The USDT December 2025 and June 2026 future directories include their respective fixed entry dates: [December 2025 BTC](https://public.bybit.com/trading/BTCUSDT-26DEC25/), [June 2026 BTC](https://public.bybit.com/trading/BTCUSDT-26JUN26/); ETH has analogous directories.

I downloaded and scanned every row of [BTC July 1, 2026 future trades](https://public.bybit.com/trading/BTCUSDT-25DEC26/BTCUSDT-25DEC262026-07-01.csv.gz) and [ETH July 1, 2026 future trades](https://public.bybit.com/trading/ETHUSDT-25DEC26/ETHUSDT-25DEC262026-07-01.csv.gz). The gzip CSV header is `timestamp,symbol,side,size,price,tickDirection,trdMatchID,grossValue,homeNotional,foreignNotional,RPI`; `timestamp` is decimal Unix seconds. There are 1,052 BTC and 761 ETH rows for the day. **Neither file has a trade in [2026-07-01 00:00:00, 00:05:00) UTC.** The earliest BTC trade is 00:10:31.474 and ETH 00:08:00.486 UTC. This blocks the unchanged trade-price five-minute entry on Bybit for 2026 H2. An order book might have contained quotes then, but an historical July 1 quote was not verified; no executable fill or substitute later entry is inferred.

Bybit's [current order-book REST method](https://bybit-exchange.github.io/docs/v5/market/orderbook) returns a snapshot and has no historical timestamp parameter. The inspected [public archive root](https://public.bybit.com/) lists `spot/` and `trading/` but no book-history directory. This does **not** prove that Bybit has no historical book dataset through another channel; it means no first-party past bid/ask archive was verified in this assessment. A [Bybit guide](https://www.bybit.com/en/learn/bybit-guide/how-to-create-a-bybit-api-key) describes historical order-book snapshots generally, but it did not provide a verified 2026-07-01 BTC/ETH dated-future book file here. Public archive downloads did not require authentication or display a fee; no general pricing or availability guarantee was established.

Bybit also has [BTC/ETH USDC spot archives](https://public.bybit.com/spot/) and dated USDC future directories with the fixed start dates in [2023 H2](https://public.bybit.com/trading/BTC-29DEC23/), [2024 H1](https://public.bybit.com/trading/BTC-28JUN24/), [2024 H2](https://public.bybit.com/trading/BTC-27DEC24/), [2025 H1](https://public.bybit.com/trading/BTC-27JUN25/) and [2025 H2](https://public.bybit.com/trading/BTC-26DEC25/), with ETH analogues. These are suitable for a **separately specified USDC** historical check; they do not create a continuous USDT track back to 2022. The [Bybit contract-format reference](https://bybit-exchange.github.io/docs/v5/enum) distinguishes USDT expiry names such as `BTCUSDT-21FEB25` from USDC expiry names such as `BTC-24MAR23`.

## Reproducible next gate

1. The OKX 2022-2023 fixed price screen **has run**, under the [pre-registered local protocol](okx_six_month_2022_2023_price_screen_protocol.md), using the [replay script](../scripts/okx_six_month_2022_2023_price_screen.py) and 32 first-party spot/futures ZIPs with locally recorded SHA256 values. The [local JSON report](../outputs/okx_six_month_2022_2023_price_screen.json) records 2022 H1 +0.795%, 2022 H2 -0.463%, 2023 H1 -0.332%, and 2023 H2 +0.229% of initial capital, for **+0.228% total before financing or capital cost**. Two half-years lost money. The screen uses adverse trade prices and an illustrative fee convention; it does not establish executable depth, account-specific fees, feasible lot size or robust profit. The historical 2022 book is outside [OKX's advertised L2 period](https://www.okx.com/en-sg/historical-data), so a 2022 execution replay cannot use that first-party L2 service.
2. For 2023-2025 execution work, request exact-date OKX 400-level L2 links for all four spot/future entry/exit sides and inspect target instrument quotes before investing in large downloads. The one verified link is 159.77 MB for one BTC futures-family day, so storage/bandwidth will be material. [Example official archive](https://static.okx.com/cdn/okx/match/orderbook/L2/400lv/daily/20240101/BTC-USDT-futureschain-L2orderbook-400lv-2024-01-01.tar.gz).
3. Treat 2026 H2 Bybit as a **different** historical/prospective implementation. Its frozen five-minute trade-price entry fails on both futures; any extension to 00:08/00:10 or use of historical quotes requires an explicit new protocol and later independent evaluation. [BTC raw file](https://public.bybit.com/trading/BTCUSDT-25DEC26/BTCUSDT-25DEC262026-07-01.csv.gz); [ETH raw file](https://public.bybit.com/trading/ETHUSDT-25DEC26/ETHUSDT-25DEC262026-07-01.csv.gz).

No source here proves robust executable profit after fees, financing, account eligibility, lot-size rounding and liquidation constraints. A first-party trade archive documents transactions that occurred; it does not document how our own order would have joined or consumed the book. [OKX trade-field and order-book definitions](https://www.okx.com/docs-v5/en/), [Bybit current order-book schema](https://bybit-exchange.github.io/docs/v5/market/orderbook).
